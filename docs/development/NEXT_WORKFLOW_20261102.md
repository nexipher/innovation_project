# 后续实施路线与 Claude Code 交接

更新日期：2026-11-02。

本文是后续实施与 Claude Code 交接的统一方案。后续变化直接修改对应章节，按阶段推进并记录结果。

设计参照：[流程图 PNG](../design/forensic_agent_flow_20261102.png)、[流程说明](../design/forensic_agent_flow_20261102.md)。实际执行与结果记录在 plan.md、claude_operation_log.md，历史实验不改写。

交接入口以本文为准。plan.md、README.md 中的旧阶段和候选状态按记录日期理解；实施时将本文已确认方向同步到当前计划与架构说明，不按旧方案重新选择机器、数据范围或压缩条件。本文描述后续方案，现有管线能力仍以实际代码和验证结果为准。

## 1. 目标与已确认原则

构建 Qwen3-VL-8B 主导的主动探索 Agent：观察图片、提出假设、调用专家、读取真实结果、修正假设并自主结案。控制器负责执行与边界，不代替正常决策，不静默改判。

- 先定任务和数据，再选专家；当前聚焦全局生成检测与普通图像局部篡改。
- 沿用当前机器。采用 GenImage 八个生成器子集开展基础开发，MNW＋DIV2K 补充较新生成器评测，AutoSplice 开展局部检测与定位。
- 当前真假图统一 JPEG q95；暂不扩展 original、q85、q70 条件。统一编码不能消除来源、分辨率和历史压缩差异。
- 保留 v3 原则，运行时关闭参考后验和预计收益。不设置“两项证据后必须停止”或“所有专家必须调用”的固定规则。
- 每专家采用经核实的主要原始分数及尺度、方向、限制，不强制映射成统一概率。
- “区域观察与对齐”是辅助操作；裁剪、叠加和框比较不增加独立法证证据。
- 历史实验、轨迹和审核结果保留，不覆盖、不直接混入新版 SFT。换模型不重置数据使用历史。

总体顺序：**环境与资产整理 → 固定数据 → 专家独立评测 → 管线修整 → 小批人工验收 → 开发评价与训练 → 最终测试**。

## 2. 当前起点与目标工具组

操作日志最近的候选评测记录为 2026-10-26：100 源 × original/q95。混合条件结果不能直接当成新方案的 q95-only 结果；相同输入、权重和预处理的历史 q95 测量优先复用。

| 模型或功能 | 当前定位 | 下一步 |
|---|---|---|
| PROBE | 当前全局主检测器、固定基线 | 维持基线，检查目标数据适用性 |
| SPAI | 离线候选，并非已准入第二专家 | 在全局任务的 q95 条件验证 |
| TruFor / IML-ViT | 局部定位候选 | 同输入比较，先选一位接入 |
| 区域观察与对齐 | 拟实现辅助操作 | 实现可靠坐标、裁剪、叠加和框比较 |
| AIDE / DRCT 现有权重 | 现有开发结果不支持直接接入 | 保留记录，暂不重开全部候选 |
| NPR | 先前 JPEG 条件退化 | 暂不作为 q95 主力，重训需新证据 |

先以 **PROBE＋一位定位器＋区域观察与对齐** 跑通闭环，同时评估 SPAI 作为第二位全局专家。专家选择同时看独立性能、错误类型与 Agent 的实际使用效果，历史纠正/损害计数作为参考。

## 3. 阶段一：环境与资产整理

沿用当前机器和已验证环境，整理资产、依赖与资源使用情况。

1. 保存未提交代码，固定 Git 提交；备份未上传的审核 JSON、轨迹、实验报告和数据清单。
2. 登记权重路径、来源、大小、哈希及依赖版本；保留划分与使用历史。
3. 核查现有 Qwen3-VL-8B 与 PROBE 的加载及运行状态，再按阶段添加专家；候选依赖需要隔离时使用独立环境，保留现有可运行基线。
4. 真实冒烟确认“看图—调用—回传—引用—结案”，原始回复完整保存。
5. 核查磁盘、内存和显存余量，安排模型按需加载与 q95 数据派生。

**产物与出口：**固定代码起点、环境/资产清单、备份和通过真实闭环冒烟的基础环境。

## 4. 阶段二：固定数据、标签与 q95 协议

### 4.1 数据选择与任务分工

数据按“基础全局检测、较新生成器评测、局部编辑”分工：**GenImage＋MNW/DIV2K＋AutoSplice**。GenImage 保留稳定基线，MNW 检查较新生成器上的表现，AutoSplice 验证局部探索流程。三部分使用 q95 输入，分别报告结果。

GenImage 八个生成器为：**Midjourney、Stable Diffusion v1.4、Stable Diffusion v1.5、ADM、GLIDE、Wukong、VQDM、BigGAN**。真实图按源身份去重与分组，评测前确定分区和批次规模。

现有 MNW 包含 **Adobe Firefly v4、ByteDance Seedream v4、Google Imagen 4、Midjourney v7** 四组假图，DIV2K 提供真实图。沿用已下载资产、清单与划分，复用输入、权重和预处理一致的专家测量。

| 数据集 | 回答的问题 | 范围与限制 |
|---|---|---|
| AutoSplice（已选定） | 是否局部修改、修改在哪里、Agent 如何调查 | 已加入本地 dataset/AutoSplice/；论文报告 2,273 真图、3,621 操作图及 mask，主要由 DALL-E2 编辑；本地完整性、实际版本与许可仍须核实 |
| GenImage 八个生成器子集（已选定） | 整图是否生成、全局专家分类能力 | 复用已有资产；没有本方案需要的局部编辑 mask；八个分组分别报告 |
| MNW＋DIV2K（纳入评测） | 较新生成器上的全局检测与 Agent 表现 | 现有资产为四组各 250 张假图及 100 张 DIV2K 真图；实际清点核对，沿用已有使用历史；仅评测 |

IMD2020 留作后续扩展，本轮集中使用上述资产。

### 4.2 当前目录与用途

保留现有目录，不移动数据，继续兼容代码和历史清单：

```text
dataset/
├─ GenImage_Test/                  # 八个生成器目录
├─ Real/                           # 现有全局真实图
├─ mnw_div2k/
│  ├─ Fake/                        # MNW 四组较新生成器
│  ├─ Real/                        # DIV2K 真图
│  └─ *.json                       # 资产、输入、抽样和使用划分清单
└─ AutoSplice/
   ├─ Authentic/
   ├─ Forged_JPEG100/
   ├─ Forged_JPEG90/
   ├─ Forged_JPEG75/
   ├─ Mask/
   └─ Caption/                     # 原发布数据的文本材料
```

MNW 官方限定评测用途，因此图片及其 Agent 轨迹只进入评测，不用于 SFT、专家微调或 RL。本地 manifest 另明确禁止用于阈值拟合。DIV2K 按学术研究条款使用；GenImage、AutoSplice 的训练用途核对各自条款后登记。

MNW 假图和 DIV2K 真图来自不同来源，报告同时列内容/分辨率差异。GenImage、MNW 分开报告；Real 跨生成器组复用时说明组间依赖，汇总按源去重。

任务分别定义：局部编辑图不能直接作为“整图生成”正例，PROBE 低生成分数不自动算错；纯生成图不能随意圈一个对象作为局部篡改真值。联合报告分别表达整图判断与局部状态。

### 4.3 数据清点与划分

- 登记本地版本、完整性、来源、用途条款与磁盘需求。
- 检查真实图/编辑图配对、同源多结果、压缩版本、mask 尺寸与对齐。抽查 mask 是指定编辑范围还是实际改动范围，记录边界误差及区域外变化。
- 按源图及编辑关系划分训练、验证、最终测试；所有同源变体留在同分区，检查重复和近重复。
- MNW 沿用现有 dev_final_split.json 与清单使用历史：已用于候选选择的部分继续作为开发评测，未使用的留出部分供最终验收。清单中的状态与实际运行记录核对后确定。
- 核对专家 checkpoint 的训练数据交集。已知交集可用于工程开发，但不能宣称未见测试；既有开发样本不因换 MLLM 重新变成未见数据。
- 对照原图与 GT mask 仅用于离线评价或明确标记的训练监督，正常 Agent 不预灌这些答案。

### 4.4 q95 处理

从最高质量可获得版本出发，真假使用同一编码器、版本、质量参数和色度采样，固定颜色/方向处理及缩放规则。保留原文件与哈希，mask 无损保存并记录几何变换。

AutoSplice 固定使用 `Authentic＋Forged_JPEG100`，真假均通过同一路径生成 q95 实验输入；`Forged_JPEG90/75` 保留原位，本轮不使用。JPEG100 仍是有损编码，Authentic 也有既有压缩历史，统一的是最后一次编码条件。所有压缩变体按同源分组。

MNW 优先复用现有、编码身份一致的 q95 输入；已有 original 测量留作历史参考，本轮报告聚焦 q95。GenImage 同样从保留的原文件派生。记录源文件与派生文件哈希及编码参数，以此核对旧结果能否复用。

**产物与出口：**任务标签、文件/源图清单、哈希、用途、分区、使用历史、预处理和评测口径。

## 5. 阶段三：专家评测与保留决定

### 5.1 全局检测

在 GenImage 八个生成器分组的固定 q95 数据上比较 PROBE 与 SPAI，先复用身份一致的旧测量。各分组配对应的真实样本，报告 AUROC、固定阈值下真假召回/平衡准确率、分数分布、错误、失败、耗时和显存。使用完全相同输入，置信区间按源图重采样；真实图跨组复用时说明组间不独立，汇总统计不得重复计数同一输入。

再在 MNW 四组与 DIV2K 对应的 q95 开发评测输入上做相同比较，独立呈现较新生成器结果。已有 PROBE/SPAI 等记录逐文件核对后复用；新增 Agent 必须与对应样本的单专家结果配对。MNW 上使用已固定的阈值与配置。

阈值或概率映射若需拟合，只在训练/验证部分进行并冻结；不因低 AUROC 事后翻转方向。SPAI 不适用时，再少量考虑 SAFE 或 FreqNet，不全面重开候选搜索。

### 5.2 局部定位

在完成清点的 AutoSplice q95 数据上比较 TruFor 与 IML-ViT，完成官方预处理和适配器的同输入对照。

- 篡改图评价像素级 F1/IoU及适当排序指标，按区域面积分析；真实图单列误报与异常面积。
- 阈值和 map 到候选框的后处理在验证集确定。不能利用测试 GT 逐图选最佳阈值或 map 正反方向。
- TruFor 分别核实 map、conf、score；IML-ViT 不强行补成相同的独立分类输出。
- 如研究 PROBE/SPAI 对局部编辑的响应，单独定义任务，不混算整图生成性能。

### 5.3 重训条件

先检查加载、预处理、方向和阈值，再根据目标分布上的错误决定是否适配专家。使用允许训练的数据做小规模实验，保留原权重对照，由验证收益决定是否扩大。

**产物与出口：**逐图分数/map、专家身份与语义表、分层报告、保留/观察/退出决定。独立检测性能先评价，Agent 融合收益后评价。

## 6. 阶段四：修整管线、证据与停止逻辑

### 6.1 真实交互

首轮保留具体视觉描述与可为空的怀疑框，不强迫模型声称存在噪声或压缩异常。每轮严格执行“模型请求—真实执行—结果回传—模型读取—再次决策”，保留原始消息，避免模型自行续写专家回复。

有局部怀疑时建议调用定位器；无视觉怀疑也允许调用。专家不默认全跑，全局低生成分数不排除局部操作。

### 6.2 区域观察与对齐

原图、裁剪图和 map 使用产物 ID，保存尺寸、坐标系和变换；程序负责换算、同步裁剪、放大、叠加及框比较。保留首次怀疑框和时间，看过 map 后的框不算独立发现。

辅助操作只展示已有结果或计算几何关系，不新增法证测量。默认裁剪整图 map 供观察，裁剪图重测需适用性依据和明确输入记录；不新增含义模糊的“区域验证专家”。

### 6.3 证据包与分数

证据包按整图、区域和时间线组织，记录工具/权重、实际输入、参数、原始结果、坐标、作用范围及状态。测量只追加，假设可撤销；整图分数不自动归因到局部。

模型可见内容精简，完整数组后台留存；每轮追加必要的新结果和图片，不重复塞入所有历史。分数条不当定位图，自报 confidence 不等于专家分数或校准概率。

### 6.4 控制器与结案

- MLLM 正常输出最终答案即结案；控制器不按后验、预计收益或固定证据数量接管判断。
- 重复请求按专家、实际输入、参数与权重识别；缓存命中、失败重试不当新增独立证据。
- 停止原因区分主动结案、预算耗尽、工具不可用、协议失败、生成失败，保留最后行动及已有证据。
- 预算耗尽可明确请求 MLLM 总结；仍无结论则记录未完成，不静默补标签。
- 结论区分全局生成与局部篡改，说明证据、冲突、未评估事项。未测量、失败、未见明显异常、定位未确认分别记录。

结合 b2 审核和 KNOWN_ISSUES 修复视觉分析缺失、虚构交叉验证、未测量却排除干扰、编造专家回复、全局结论越界及标签/解释/confidence 矛盾。原始回复、框架采用结果、外部原因分别留存。

**产物与出口：**接口与日志可追溯，相关协议检查通过，真实多模态冒烟证明回传正确。运行受影响路径和仓库要求的检查，不以增加无关测试数量代替验收。

## 7. 阶段五：小批 Agent 与人工审阅

真实冒烟后，先生成约 24–32 条可逐条审阅的小批，提前固定数量、来源和任务构成。以 GenImage 与 AutoSplice 验证交互及局部流程；MNW 会话单列评测用途。不同任务分别统计。

覆盖无明显视觉异常、框不一致、专家冲突、定位误报、失败、重复请求、预算耗尽。人为注入的工程失败场景与正常检测样本分开报告。

工作台显示实际输入、完整原始对话、请求与真实返回、map/conf、辅助图、证据来源、停止原因及最终报告，并支持审核和导出。审核绑定样本 ID 与内容指纹，记录变化后需重审。

验收重点：真实调用与投递、坐标与引用准确、能调整或撤销假设、辅助观察不冒充证据、报告与结论一致。分类正确但编造证据同样不合格。修复后新建批次对照，旧批保留。

**产物与出口：**审核 JSON、问题清单和通过验收的新批次。小批只验证协议和行为，不用于宣布泛化性能。

## 8. 阶段六：开发评价与训练

### 8.1 先评价未训练 Agent

固定可复现版本，在开发/验证集上配对比较同输入单专家与 Agent；必要时加固定融合对照。按任务报告检测、定位、解释忠实度、弃权/未完成和成本。对弃权报告覆盖率，不静默排除后只报准确率。

该阶段用开发部分决定是否扩充轨迹、专家或训练；MNW 开发评测单列较新生成器表现，最终留出部分继续保留。

### 8.2 新版 SFT

从允许训练的 GenImage、AutoSplice 分区生成小份候选并审计，再按内容、难度、错误类型和行动模式扩展。MNW 及其派生轨迹独立保存在评测批次，训练入口按来源排除。

- 保存视觉观察、真实请求/返回、假设修正及结案，不只保留模板报告。
- 环境观察只作输入，loss 监督模型输出，核对角色掩码。
- 教师指导、GT 注入与自主轨迹分别标记；正常验收不提供教师帮助，不围绕 GT 编造解释。
- 保留有效失败假设与合理不确定性；严重问题进入拒绝或待修集合。
- 许可、源图隔离与批次身份核对后做小规模 SFT，评价训练前后检测、证据忠实度和行动行为。

SFT 稳定后再考虑 RL；借鉴 ATAR 工具选择和忠实度监督、ForenAgent 执行闭环，不直接复制隐式工具替换或强制裁剪奖励。

**产物与出口：**审核训练集、配置、模型和训练前后配对开发结果，再决定是否扩大训练。

## 9. 阶段七：最终冻结与留出测试

专家、提示词和训练选择完成后，冻结代码、所有权重、提示词、预处理、阈值、后处理和预算，再运行最终留出集。

分别报告任务性能、真图误报、局部漏检、解释幻觉、弃权、未完成和成本。若根据结果再调整方案，该集合此后属于已使用数据，不能继续作为未见最终测试。

## 10. Claude Code 的近期任务与资源安排

| 顺序 | 任务 | GPU |
|---|---|---|
| 1 | 沿用当前机器，核查资产、备份、代码起点、依赖和资源余量 | 否；真实冒烟需要 |
| 2 | 清点 GenImage、MNW/DIV2K、AutoSplice；核实配对与 mask，整理 q95 复用记录和用途划分 | 否 |
| 3 | 按固定输入评测全局与局部候选，分别报告 GenImage、MNW 和 AutoSplice | 通常需要 |
| 4 | 确定专家后修整证据、坐标、辅助操作与停止路径 | 主要 CPU；回传冒烟需 GPU |
| 5 | 小批运行、工作台人工审阅与新批对照 | 推理需 GPU；审阅不需要 |
| 6 | 开发评价、候选轨迹生成、审计与小规模 SFT | 生成/训练需 GPU |
| 7 | 最终方案冻结后的留出验收 | 通常需要 |

当前直接从现有目录清点 GenImage、MNW/DIV2K 与 AutoSplice，整理缺失项、源图分组、用途和可复用测量，随后按表推进。优先复用已有环境和结果，把新增计算用于定位专家与真实 Agent 验证。
